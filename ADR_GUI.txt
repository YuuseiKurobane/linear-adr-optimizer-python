ADR GUI design
==============

Preset order in this document:
Potato | Lite | Medium | Medium-High | High

General GUI instructions
------------------------

- The GUI should default to Medium-High when no user choice has been made.
- The GUI may recommend a preset automatically, but that recommendation belongs only in the Anki add-on GUI. The CLI should not auto-select a preset.
- The user should be free to override the recommended preset.
- The visible preset set is finalized as: Potato, Lite, Medium, Medium-High, High.
- Maximum is intentionally removed. Users who want beyond-High behavior can manually edit advanced values.
- Preset tiers should communicate runtime cost clearly. The intended behavior is that each higher tier is meaningfully slower and usually more accurate.
- The GUI should expose settings in three layers:
  - Layer 1: Basic settings for ordinary users.
  - Layer 2: Advanced settings for users who want to edit the preset mechanics.
  - Layer 3: Hidden advanced settings for rarely changed internals.
- Layer 2 and Layer 3 should keep exact config names. Do not replace them with friendly alternate names.
- When a preset is selected, Layer 2 should show the preset values that are being applied.
- If a user edits a preset-managed value, the GUI should treat the run as a custom preset derived from the selected preset.
- `include_original` should default off in the GUI. Its purpose is for users to manually insert a past ADR parameters.
- Manual reference points from `include_original` or `inspect_point` should be final-only comparison points. They should not steer search promotions, bridge neighborhoods, or hillclimb seeding unless the same point is naturally found by the automated search.
- If `target_dr` is very high, especially 94% or above, the GUI should suggest raising `fixed_dr_end_pct` to 99 so the fixed-DR baseline covers the relevant area.
- The result screen should emphasize the practical labels first: Recommended, Release, Efficient, Memory, Calm, Aggressive, and Fixed-DR comparison points. Maximum Spread can remain visible but should not be treated as a primary objective.

Layer 0: Misc app management tools
----------------------------------

Layer 0 should cover app-level run selection, input selection, and output management before ordinary simulation/search settings.

- quality_preset
    medium-high
    User label: Search quality preset
    Valid values: potato, lite, medium, medium-high, high

- export
    app-managed
    User label: Export data source
    Notes: May be a specific export JSONL file or a directory containing adr-input-*.jsonl files.

- preset
    Yuusei
    User label: Deck preset
    Notes: Selects the deck_preset.name row from the export data. Exact matches win before partial matches.

- output_dir
    app-managed
    User label: Output folder
    Notes: Directory where a normal run writes the Plotly HTML plot and JSON summary. With --matplotlib, it writes the legacy PNG plot and JSON summary. With a point-only flag, it writes only one TXT file.

- threads
    0
    User label: Rust worker threads
    Notes: 0 means use all available CPU cores.

- matplotlib
    false
    User label: Legacy Matplotlib output
    CLI flag: --matplotlib
    Notes: Restores the old PNG plotting behavior. Plotly HTML is the default because Matplotlib is not compatible with Anki.

- recommended_only
    false
    User label: Recommended TXT only
    CLI flag: --recommended-only
    Notes: Writes one TXT file and prints normal terminal progress plus the final Recommended point. Does not write plot HTML/PNG or summary JSON.

- aggressive_only
    false
    User label: Aggressive TXT only
    CLI flag: --aggressive-only
    Notes: Writes one TXT file and prints normal terminal progress plus the final Aggressive point. Mutually exclusive with other point-only flags.

- calm_only
    false
    User label: Calm TXT only
    CLI flag: --calm-only
    Notes: Writes one TXT file and prints normal terminal progress plus the final Calm point. Mutually exclusive with other point-only flags.
